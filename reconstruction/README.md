# Historical event reconstruction — AMIL1 and MNLM6 pilots

This directory is an **independent, opt-in science pipeline**, separate from the hourly dashboard. The source spreadsheet values remain untouched. The existing site remains unchanged until verified events are approved for publication.

Pilot sites: AMIL1 / USGS 07375430 and MNLM6 / USGS 02492360 (West Hobolochitto, **not** CREM6 / East Hobolochitto).

## Inputs and method

The processor consumes a carefully staged hourly QPE raster inventory and dated event windows. Its inputs are intentionally **not** generated automatically from the historic spreadsheets:

- `--manifest`: CSV with `valid_end_utc,path,product,units`, where the timestamp is the **end** of each hourly precipitation interval. Each raster must be a geographic CRS (EPSG:4326 or equivalent), matching grid transform and shape for a given event. Supported `units`: `mm` and `in`; `product` must be consistently and explicitly specified per event, e.g. `MRMS_Pass2` or `StageIV`. Never silently combine product versions.
- `--events`: CSV with `event_id,nwsli,rain_start_utc,rain_end_utc,crest_time_utc,crest_ft`. Event windows are **explicit**, not inferred from legacy Date/TC/Periods. Rain start is inclusive and rain end is exclusive; required hourly QPE timestamps are start+1h through end. Crest is an independently observed stage with recorded timestamp. All times must contain a UTC offset (prefer `Z`).
- `--basins`: `data/basins.geojson` as generated by the dashboard's NLDI step. The program selects the **full upstream basin** by USGS ID; it never selects `data/reaches.geojson`. This polygon is not certified to match the historical LMRFC study boundary.
- `--output`: JSON result file (default `reconstruction/results/pilot_events.json`). No input is overwritten.

Run from the repository root after installing `requirements.txt`:

```bash
python reconstruction/run_pilots.py --manifest path/to/qpe_manifest.csv --events path/to/observed_events.csv --basins data/basins.geojson
python -m unittest discover -s reconstruction/tests -v
```

Example manifest (file paths are relative to the manifest's folder):

```csv
valid_end_utc,path,product,units
2026-10-31T01:00:00Z,rasters/20261031_01.tif,MRMS_Pass2,mm
2026-10-31T02:00:00Z,rasters/20261031_02.tif,MRMS_Pass2,mm
```

Example observed event (illustrative **schema**, not an asserted historical flood):

```csv
event_id,nwsli,rain_start_utc,rain_end_utc,crest_time_utc,crest_ft
example-001,AMIL1,2026-10-31T00:00:00Z,2026-10-31T02:00:00Z,2026-11-01T14:00:00Z,10.0
```

## Quality gates

Each accepted event requires every expected hourly grid, matching raster geometry and valid full-basin coverage in every hour. Rainfall is summed across complete hourly rasters before the existing `update.py` area-weighted whole-basin calculation, including valid zero-rain cells. It does not compute wet-area MAP or fabricate missing grids. Raster files may be GeoTIFF or another GDAL-readable raster, provided the documented units/CRS/metadata are correct. Events with insufficient coverage, mismatched products, overlapping or missing hours, or invalid timestamps **fail closed**.

### Archive acquisition (not yet implemented)

Hourly Stage IV (early-2000s onward, subject to archive coverage) and archived MRMS Pass 2 must be downloaded/converted into the manifest before running this code. Pre-MRMS work will use Stage IV where verified, then station/gridded daily precipitation with a **separate daily-resolution method** (not this hourly pipeline). Daily data must not be disguised as six-hour rain periods. Obtaining original LMRFC MAP/basin methods remains a science task.

### Current limitations / next gates

1. Independently retrieve verified USGS/NWPS stage hydrographs, crest timestamps and site datum histories; event CSV is deliberately explicit to prevent false crest associations.
2. Reconcile QPE product availability, archive grid/units and events for **both** pilots; test Stage IV versus MRMS in their actual overlapping years.
3. Verify basin geometry and event-window definition with LMRFC; compare matched calculated MAP/crest with immutable legacy records as **separate series**.
4. Only then publish new plotted events (same MAP-inches X / crest-feet Y display as the legacy workbook), add source toggles, and enable scheduled event processing.

No historical floods, new validated crest relationships, or published reconstruction records are claimed by adding this scaffold.
